# TraceForge v0.3 Dashboard Notes

TraceForge v0.3 adds a local browser dashboard. The goal is to keep the recording engine CLI-first while making analysis visual and easier to share in screenshots or demos.

## Command

```bash
traceforge dashboard
```

Optional flags:

```bash
traceforge dashboard --host 127.0.0.1 --port 8787 --no-open
```

## Architecture

```text
traceforge dashboard
    ↓
Python standard-library HTTP server
    ↓
SQLite trace database under .traceforge/
    ↓
JSON API endpoints
    ↓
Single-page browser UI
```

## Why a local server?

The browser cannot directly execute local commands or freely inspect project files. TraceForge keeps command recording in the CLI and uses a local server only for reading trace data and presenting it visually.

## Endpoints

- `GET /` — dashboard UI
- `GET /api/health` — version and root path
- `GET /api/runs?limit=100` — recent runs
- `GET /api/runs/<run_id>` — run detail, events, changed files, stdout, stderr, and patch

## Current limitation

This dashboard is intentionally dependency-free. A future Next.js dashboard can replace or extend it once the trace data model is stable.
