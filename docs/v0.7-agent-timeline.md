# TraceForge v0.7 — Agent Timeline

TraceForge v0.7 turns a run from a final result into a replayable timeline.

## New timeline events

A recorded command can now include events such as:

- `run.started`
- `command.started`
- `security.checked`
- `git.snapshot.before`
- `stdout.chunk`
- `stderr.chunk`
- `process.exited`
- `artifact.written`
- `git.snapshot.after`
- `git.diff.captured`
- `file.changed`
- `security.warning`
- `report.generated`
- `json.exported`
- `run.finished`

Each event stores a timestamp plus structured JSON data. Most runtime events also include `offset_ms`, which shows when the event occurred relative to the run start.

## CLI timeline view

```bash
traceforge timeline <run_id>
traceforge timeline <run_id> --json
```

## Dashboard changes

The dashboard now shows event counts in the summary and run list. The run detail timeline uses event-kind badges, relative offsets, and short data previews so the user can understand what happened without opening raw JSON.

## Why this matters

AI coding agents are not just final patches. They are sequences of actions and observations. Timeline events are the foundation for future support for MCP tool calls, coding-agent adapters, run replay, and richer failure analysis.
