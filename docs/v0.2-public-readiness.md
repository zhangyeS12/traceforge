# V0.2 Public Readiness Notes

V0.2 turns the original MVP into something closer to a public developer tool.

## What changed

### 1. Shellless execution by default

The original MVP converted command arguments into one shell string. On Windows, POSIX-style quoting can break commands such as:

```powershell
traceforge run -- python -c "print('hello')"
```

V0.2 passes command arguments directly into `subprocess.Popen` by default. This is safer and more cross-platform.

Use `--shell` only when shell syntax is required:

```powershell
traceforge run --shell -- "npm test && npm run lint"
```

### 2. Live output streaming

V0.2 supports:

```powershell
traceforge run --live -- python hello.py
```

This teaches:

- `subprocess.Popen`
- `stdout` and `stderr` pipes
- background threads
- capturing output while displaying it to the user

### 3. Environment doctor

```powershell
traceforge doctor
```

This checks Python, Git, Rust, Cargo, Node, npm, workspace status, database status, and whether the current folder is a Git repository.

This teaches:

- `shutil.which`
- executing version commands
- developer experience design
- machine-readable JSON output with `--json`

### 4. JSON export

```powershell
traceforge export <run_id>
```

This writes a `trace.json` file with run metadata, events, changed files, stdout, stderr, and patch contents.

This teaches:

- data serialization
- public schema design
- interoperability with future web dashboards or AI analyzers

### 5. Clean command

```powershell
traceforge clean --yes
```

This removes local runs, reports, and database while keeping config.

This teaches:

- local workspace management
- safe destructive commands
- confirmation flags

## Why these changes matter

A public CLI tool needs more than core logic. It needs:

- predictable behavior across platforms
- clear help messages
- environment diagnostics
- cleanup commands
- export formats
- useful documentation

This is the difference between a school script and a usable developer tool.
